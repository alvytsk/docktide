# M3 Compose Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Group Compose containers by project in the container list, and add a project logs page that merges every container's logs in time order with service tags and chips.

**Architecture:** Rust only gains `ContainerSummary.compose`, read from the Compose labels the list API already returns. Everything else is frontend. Grouping is a pure function over the containers query. The project logs page runs one existing `open_logs` stream per container through a `ProjectLogSession` kept outside React. It merges lines by timestamp in a generalized `LogBuffer` and renders through a `LogView` extracted from the Logs tab.

**Tech Stack:** Rust (Bollard 0.21.1, serde, ts-rs), React 19, TanStack Router/Query/Virtual, Zustand, Vitest via `vp test`. No new dependencies.

**Spec:** `docs/specifications/m3-compose.md`. Read it first. FR, AC, and D numbers below refer to it.

## Global Constraints

- No new Rust or npm dependencies. No new Tauri commands (D2): the page uses `openLogs` / `closeLogs` from `src/lib/ipc.ts`.
- Work on branch `m3-compose`, one commit per task, in the message style of `git log` (`Add … (M3 slice Sn)`).
- At the end of every task, these pass: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings` (pedantic is on), `cargo test --workspace`, `pnpm check`, `pnpm test`, `pnpm typecheck`.
- DTOs derive `ts_rs::TS` under `#[cfg_attr(test, derive(ts_rs::TS))]`, use `#[serde(rename_all = "camelCase")]`, and are listed in the `bindings` test in `crates/docktide-core/src/lib.rs`. Regenerate them with `DOCKTIDE_UPDATE_BINDINGS=1 cargo test -p docktide-core bindings`.
- Docker integration tests touch only containers labelled `io.docktide.test=true` and are `#[ignore = "requires Docker"]`.
- Compose labels: `com.docker.compose.project`, `com.docker.compose.service`, `com.docker.compose.container-number`, `com.docker.compose.oneoff`.
- Values from the spec: tail choices 100, 1,000 (default), 10,000, All, per container; buffer capacity 10,000 entries across the project. Service colours are ANSI palette indices `[2, 3, 4, 5, 6, 10, 11, 12, 13, 14]`, never 1 or 9.
- Copy, verbatim: `N services`, `R/T running`, `Logs`, `No containers running. Logs resume when one starts.`, `Logs for <tag> failed: <message>`, `Docker is not reachable.`, `No containers in project <name>.`, `N lines skipped from <tag> (output too fast)`, `No log output yet`, `Older lines are no longer shown.`
- "Running" in counts, colours, footers, and the reopen rule means `state === "running"` only.
- Stream data (log lines) never goes into TanStack Query or Zustand (overview §4). The collapse state and hidden services are UI state: collapse goes in Zustand, and hidden services live in the session.

## Review Focus

1. **A line with an empty timestamp.** Rust's `split_timestamp` yields `""` when Docker sends a line without one. Expected: the line sorts right after the previous line from the same container, not at the top of the view. Test in Task 4: `a line without a timestamp stays after its container's previous line`.
2. **React StrictMode, or quick navigation, closes the session before `openLogs` resolves.** Expected: the late subscription is closed the moment it resolves, and no Engine connection leaks (AC-10). Test in Task 5: `a stream that resolves after close is closed at once`.
3. **`docker compose up --force-recreate` replaces `api` with a new container.** Expected: the old and new containers both tag as `api`, never `api-1`/`api-2`, because only one exists at a time. The old lines keep their tag. Test in Task 5: `a recreated container keeps the plain service tag`.
4. **Changing the tail while streams are still opening.** Expected: every old subscription is closed, the buffer starts empty, and lines from the old streams that arrive late are ignored. Test in Task 5: `changing the tail drops late lines from the old streams`.
5. **A stopped service whose stream ends right away.** Expected: no reopen loop while later query results keep saying `exited`. It reopens exactly once when a newer result says `running`. Test in Task 5: `an ended container reopens once per newer running result`.

- Produces:
  - `tags.ts`:
    - `tagFor(c: ContainerSummary, members: ContainerSummary[]): string`. One-off containers get `c.name`. A service with more than one non-one-off member in `members` gets `service-N`, where N is `number ?? 1`. Otherwise the tag is `service`.
    - `serviceColor(service: string): string` returns `` `var(--ansi-${index})` ``. It uses an FNV-1a hash of the name to pick from `[2, 3, 4, 5, 6, 10, 11, 12, 13, 14]`.
  - `session.ts`:
    - `type LogsIpc = { open: typeof openLogs; close: typeof closeLogs }`. The default is the real functions; tests pass fakes.
    - `type SourceInfo = { service: string; tag: string }`.
    - `class ProjectLogSession`, built with `new ProjectLogSession(project: string, ipc?: LogsIpc)`. Public fields: `project`, `tail: LogTail` (1000), `buffer: LogBuffer`, `hidden: Set<string>` of services, `sources: Map<string, SourceInfo>` (container id → info, kept for removed containers), `streams: Map<string, StreamStatus>`, and `version: number`.
    - `start(onChange: () => void, hooks: { onEnded(): void; onConnectionLost(): void }): () => void`. It attaches the callbacks; the returned function closes every open subscription.
    - `sync(members: ContainerSummary[], fetchedAt: number): void` applies membership and the reopen rule. When `members` is empty, nothing is closed except removed containers' streams.
    - `retry(id: string): void`, `setTail(tail: LogTail): void` (closes all, new buffer, reopens current members), `toggleService(service: string): void`, `clear(): void`.
    - `services(): string[]`: services with a member, or with lines in the buffer, sorted.
  - `export function projectSession(project: string): ProjectLogSession` keeps the most recent project's session at module level, as `sessionFor` does in `use-log-stream.ts`.

Rules, from FR-2:

- `sync` opens a stream for each member without one, using `tail` or, when `buffer.resumePoint(id)` is set, `after`. It closes and forgets streams for ids no longer in `members`. It updates `sources` for current members.
- On an `ended` event, the stream records `endedAt = Date.now()` and calls `hooks.onEnded()`.
- `sync` reopens an ended stream, with `after`, when its member is `running`, `fetchedAt > endedAt`, and `fetchedAt` has not been used for that id yet.
- A `notFound` error is treated like `ended`. A connection-level error (`isConnectionLevel`) marks that stream `disconnected` and calls `onConnectionLost`. Any other error marks it `{ kind: "error", error }`.
- Every handler checks a per-stream `closed` flag, as in `LogSession.open`. A subscription id that resolves after close is closed at once.
